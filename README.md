# WinFlake

Снег на рабочем столе Windows. Он падает поверх всех окон и ложится сугробами на верхние края окон, на панель задач и на низ экрана.
Снег можно смахнуть курсором или слепить из него снежки и снеговика. Клики проходят сквозь снег, поэтому работать он не мешает.

Нативное приложение на C++20 + Win32 + Direct3D 11 + DirectComposition: один exe без зависимостей и без установщика.

## Возможности

- **Снегопад на всех мониторах.** Снежинки разного размера, с покачиванием. На мониторах с разным масштабом (DPI) они выглядят одинаково.
- **Сугробы.** Снег копится на верхних краях окон, на панели задач и внизу экрана. Склоны держат угол естественного откоса, лишнее осыпается с краёв.
- **Учёт z-order.** На части окна, закрытой другим окном, снег не ложится, а уже лежащий там осыпается.
- **Окно сдвинули, свернули или закрыли** — его сугроб падает вниз. **Изменили ширину** — сугроб растягивается или сжимается.
- **Варежка.** Быстрое движение курсора смахивает снег, и он разлетается по направлению движения.
- **Лепка.** Зажмите **Ctrl + левый Alt**, нажмите на сугроб и катите снежок: он растёт. Снежки падают, сталкиваются и ставятся друг на друга (снеговик).
- **Меню в трее.** Пауза, снегопад (лёгкий / ровный / метель), ветер (штиль / влево / вправо и сила), «Лопата» (убрать весь снег), пауза в полноэкранных приложениях, автозапуск.
- **Горячая клавиша паузы:** **Ctrl + Alt + S**.
- **Автопауза.** Снег сам ставится на паузу, когда открыто полноэкранное приложение или игра, при блокировке и сне, а также на батарее в режиме энергосбережения.
- **Настройки** хранятся в `%APPDATA%\WinFlake\settings.ini`.

## Требования

- Windows 10 1903+ или Windows 11, x64.
- Видеокарта с Direct3D 10+. Если её нет, используется программный рендер WARP.

## Сборка на Windows (MSVC)

Нужны **Visual Studio 2022 Build Tools**: workload «Desktop development with C++» с MSVC v143 и Windows 11 SDK. CMake 3.21+ входит в их состав.

В «Developer PowerShell for VS 2022» выполни:

```powershell
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure   # тесты симуляции
```

Готовый файл: `build\Release\WinFlake.exe`. CRT слинкован статически, поэтому VC++ Redistributable не нужен.

## Сборка без Windows (macOS / Linux)

### Тесты симуляции, нативно

`src/sim/` написан на чистом C++ без WinAPI, поэтому его тесты собираются где угодно:

```sh
cmake -S . -B build/host -DCMAKE_BUILD_TYPE=Debug -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined"
cmake --build build/host
ctest --test-dir build/host --output-on-failure
```

### Кросс-сборка exe через mingw-w64

```sh
brew install mingw-w64            # macOS (~1.5 ГБ); на Linux: apt install mingw-w64
cmake -S . -B build/win -DCMAKE_TOOLCHAIN_FILE=cmake/mingw-w64-x86_64.cmake
cmake --build build/win
x86_64-w64-mingw32-strip build/win/WinFlake.exe   # необязательно: ~2.5 МБ → ~0.4 МБ
```

Exe собирается статически, его можно сразу копировать на Windows.

### Проверка шейдеров без Windows

HLSL компилируется на Windows при запуске. Синтаксис можно проверить заранее через glslang (`brew install glslang`).
Вырежи текст между `R"hlsl(` и `)hlsl"` из `src/render/shaders.h` в `shaders.hlsl`, затем:

```sh
for e in vs_disc:vert vs_pile:vert ps_flake:frag ps_ball:frag ps_pile:frag; do
  glslangValidator -D -e ${e%%:*} -S ${e##*:} -V shaders.hlsl -o /dev/null; done
```

### GitHub Actions

`.github/workflows/build.yml` на каждый push:
- собирает `WinFlake.exe` на MSVC (артефакт **WinFlake-x64**);
- гоняет тесты симуляции на MSVC и на Linux с ASan/UBSan.

## Запуск

Запусти `WinFlake.exe`. Окна приложение не открывает, в трее появляется снежинка, а меню открывается правой кнопкой мыши по ней.
Второй экземпляр не запускается.

Exe не подписан, поэтому Windows SmartScreen может показать «Система Windows защитила ваш компьютер». Нажми **Подробнее**, затем **Выполнить в любом случае**.

## Как это устроено

```
src/
  sim/              чистый C++: снежинки, сугробы (карты высот), видимость по z-order,
                    варежка, снежки. Без WinAPI, покрыт тестами (tests/).
  app/              wWinMain, цикл, трей и меню, settings.ini, автозапуск, автопауза, манифест, иконка
  overlay/          прозрачное click-through окно на весь виртуальный экран; список мониторов
  render/           D3D11 + DirectComposition; 3 инстансных draw call: сугробы, снежки, снежинки
  windows_tracker/  окна верхнего уровня: EnumWindows + DWM-границы + SetWinEventHook
  input/            курсор и клавиши опросом каждый кадр (без хуков), Ctrl+Alt+S
tools/make_icon.py  генератор src/app/snowflake.ico
```

- **Оверлей.** Окно `WS_EX_NOREDIRECTIONBITMAP | TRANSPARENT | LAYERED | TOPMOST | TOOLWINDOW | NOACTIVATE`.
  Swap chain создаётся через `CreateSwapChainForComposition` (`DXGI_ALPHA_MODE_PREMULTIPLIED`). `UpdateLayeredWindow` не используется.
  В режиме лепки у окна временно снимается `WS_EX_TRANSPARENT`.
- **Цикл.** Один поток. `MsgWaitForMultipleObjectsEx` ждёт сообщения и высокоточный таймер с частотой 60 Гц.
  Симуляция идёт с фиксированным шагом 1/60 с. Кадр рисуется, когда waitable-объект swap chain готов (frame latency = 1).
  На паузе нет ни таймера, ни кадров, и CPU почти не тратится.
- **Сугробы.** У каждого окна есть одномерная карта высот с шагом 2 px × масштаб.
  Снежинка ложится, когда пересекает линию снега на видимом участке кромки. Видимый участок — это кромка минус окна выше по z-order минус области вне мониторов.
  Края развёрнутых окон у верха экрана не считаются.
  Склоны сглаживаются до угла откоса. Излишек с краёв и в «дыры» превращается в падающие частицы.
- **Трекинг окон.** Учитываются только видимые окна, кроме свёрнутых, cloaked (другие рабочие столы), tool windows, click-through и полностью прозрачных.
  Панели задач (`Shell_TrayWnd`, `Shell_SecondaryTrayWnd`) учитываются всегда.
  Список пересобирается по событиям SetWinEventHook и не реже раза в 500 мс.
- **Координаты.** Физические пиксели (Per-Monitor DPI Aware V2 через манифест).
- **Шейдеры** компилируются при запуске через `d3dcompiler_47.dll`, который входит в Windows 10+.
- **Восстановление.** Окно и устройство пересоздаются при смене мониторов, перемещении панели задач, потере D3D-устройства и после сна или разблокировки.

## Известные ограничения

- **Ctrl + Alt.** Пока они зажаты, весь экран принимает клики в снег, а не в окна. Используется только **левый** Alt, чтобы AltGr на польской, немецкой и других раскладках не включал лепку.
- **Поверх снега может оказаться** оболочка Windows 11 (меню «Пуск», всплывающие панели трея, некоторые системные окна). Под ними снег не исчезает.
- **Снег на окне, которое тащат, сразу осыпается.** Так задумано, но во время перетаскивания на окне снега нет.
- **Контекстные меню** приложений тоже могут закрыть сугроб: тогда он осыпается в этом месте.
- **Swap chain покрывает прямоугольник вокруг всех мониторов.** Если мониторы стоят «лесенкой», часть видеопамяти тратится зря. Предел — 16384×16384 (D3D11).
- **Снег не рисуется поверх** экрана блокировки, UAC и игр в эксклюзивном полноэкранном режиме. Это ограничение Windows.
- **Автопауза** определяет полноэкранность через `SHQueryUserNotificationState`. Если она срабатывает зря, её можно отключить в меню.
